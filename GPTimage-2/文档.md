API Reference

图片与视频生成接口
本站按模型能力提供图片生成、图片编辑和视频生成接口。先在模型广场查看模型的 supported_endpoint_types，再选择对应请求格式；同一个资源组内的模型不保证使用同一种协议。

Base URL
https://api.rtoc.cc
Auth
Authorization: Bearer sk-...
Content-Type
application/json / multipart/form-data
按端点类型选择接口
模型广场会展示每个模型支持的端点类型。请按端点类型选接口，不要按渠道或模型来源猜请求体。

端点类型	接口	请求格式	用途
openai	POST /v1/chat/completions	OpenAI Chat	聊天、多模态输入，以及聊天兼容生图模型。
gemini	POST /v1beta/models/{model}:generateContent	Gemini 原生	已经按 Gemini 原生请求体开发的客户端。
image-generation	POST /v1/images/generations	OpenAI Images	文生图，适用于明确标注 image-generation 的模型。
image-generation	POST /v1/images/edits	OpenAI Images	参考图、图生图、改图或局部编辑，取决于具体模型能力。
openai-video	POST /v1/videos	任务接口	异步视频生成。

游乐场兼容层
游乐场使用统一的图片生成入口，后端按模型能力分流：标注 image-generation 的模型走 Images 风格任务；标注 openai/gemini 且带 image 标签的聊天兼容生图模型，会在后端转换为聊天兼容请求。这个兼容层是按能力判断，不绑定某个渠道。

游乐场上传或粘贴的图片会保存为 /pg/assets/... 资源。该资源是服务端持久化文件，不是浏览器临时缓存；同时受用户容量、文件数量和生命周期清理策略限制。

聊天兼容生图
当模型支持 openai 端点且用于生图时，使用 /v1/chat/completions。文生图可把提示词写成字符串；图生图或参考图使用多模态 content parts。

curl https://api.rtoc.cc/v1/chat/completions \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-3.1-flash-image",
    "stream": false,
    "messages": [
      {
        "role": "user",
        "content": "生成一张 1:1 产品摄影图：白色陶瓷马克杯，浅色背景，柔和棚拍光。只返回图片。"
      }
    ],
    "extra_body": {
      "google": {
        "image_config": {
          "aspect_ratio": "1:1",
          "image_size": "1K"
        }
      }
    }
  }'
参考图 / 图生图
聊天兼容生图模型支持在 messages[].content 中传参考图。图片可以是 HTTPS URL、data URL base64，或游乐场上传后得到的 /pg/assets/... 地址。

{
  "model": "gemini-3.1-flash-lite-image",
  "stream": false,
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "参考这张杯子图，生成新的 1:1 产品图：杯子改成哑光红色，浅色背景，只返回图片。"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://example.com/reference.jpg"
          }
        }
      ]
    }
  ],
  "extra_body": {
    "google": {
      "image_config": {
        "aspect_ratio": "1:1",
        "image_size": "1K"
      }
    }
  }
}
聊天兼容参数
参数	位置	说明
model	请求根字段	模型广场中的公开模型名。
messages	请求根字段	OpenAI Chat 消息数组。参考图使用 content parts 数组。
stream	请求根字段	生图建议设为 false，便于一次性解析返回图片。
group	请求根字段	可选。需要指定图片资源组时填 生图。
temperature / top_p / max_tokens / seed	请求根字段	通用聊天参数；实际影响取决于模型。
messages[].content[].image_url.url	消息内容	参考图 URL、data URL base64 或 /pg/assets/...。
extra_body.google.image_config.aspect_ratio	扩展字段	图像比例，例如 1:1、16:9、9:16。在 extra_body 中使用 snake_case。
extra_body.google.image_config.image_size	扩展字段	图像尺寸档位，例如 1K 或 2K。在 extra_body 中使用 snake_case。
extra_body.google.imageConfig、aspectRatio、imageSize 这类 camelCase 写法不会被聊天兼容扩展接受；请使用上表中的 snake_case。Gemini 原生接口仍按原生请求体使用 camelCase。

GPT Image 2 图片接口
gpt-image-2 只使用 OpenAI Images 接口：文生图调用 POST /v1/images/generations，上传参考图、图生图、改图或遮罩编辑调用 POST /v1/images/edits。不要把该模型发送到 /v1/chat/completions。

文生图
curl https://api.rtoc.cc/v1/images/generations \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "白色陶瓷马克杯产品摄影，浅灰背景，柔和棚拍光",
    "size": "1024x1024",
    "quality": "medium",
    "output_format": "png",
    "n": 1
  }' > response.json

jq -r '.data[0].b64_json' response.json | base64 --decode > result.png
参考图 / 图生图
/v1/images/edits 使用 multipart/form-data。单张参考图传一次 image[]；多张参考图重复传入同名字段。

curl https://api.rtoc.cc/v1/images/edits \
  -H "Authorization: Bearer sk-your-key" \
  -F "model=gpt-image-2" \
  -F "image[]=@reference-1.png" \
  -F "image[]=@reference-2.jpg" \
  -F "prompt=保留第一张图的主体外观，参考第二张图的配色，生成新的产品图" \
  -F "size=1024x1024" \
  -F "quality=medium" \
  -F "output_format=png" \
  -F "n=1" > response.json

jq -r '.data[0].b64_json' response.json | base64 --decode > edited.png
遮罩编辑
在 edits 请求中增加 -F "mask=@mask.png"。遮罩作用于第一张参考图；遮罩与第一张图必须格式相同、像素尺寸相同且小于 50 MB，遮罩文件必须包含 alpha 通道。遮罩用于引导编辑区域，具体修改要求仍写进 prompt。

gpt-image-2 参数
参数	可用值与用法
model	固定为 gpt-image-2。
prompt	必填。描述要生成的画面，或明确说明如何使用、修改参考图。
image[]	仅 edits 接口。上传一张或多张本地图片；多图时重复该字段。
mask	仅 edits 接口。可选的 PNG 遮罩，作用于第一张参考图。
n	正整数，默认 1，控制本次返回的图片数量。
quality	low、medium、high 或 auto；默认 auto。草稿优先使用 low，成品使用 medium 或 high。
size	auto，或满足约束的任意 宽x高。常用值：1024x1024、1536x1024、1024x1536、2048x2048、2048x1152、3840x2160、2160x3840。
size 约束	两条边都必须是 16 的倍数；最长边不超过 3840；长短边比例不超过 3:1；总像素在 655,360 到 8,294,400 之间。
output_format	png、jpeg 或 webp；默认 png。追求更快返回可使用 jpeg。
output_compression	仅用于 jpeg/webp，范围 0 到 100。
background	auto 或 opaque。gpt-image-2 不支持 transparent。
moderation	auto 或 low；默认 auto。
input_fidelity	不要传。gpt-image-2 会自动以高保真处理所有输入图片，不能手动调整。
接口返回 JSON，图片内容位于 data[].b64_json。生成通常需要几十秒，复杂请求可能接近 2 分钟；客户端超时建议设置为至少 180 秒。

Gemini 原生接口
如果客户端已经使用 Gemini 原生请求体，可以调用 /v1beta/models/{model}:generateContent。路径中的 {model} 使用模型广场中的公开模型名。

curl https://api.rtoc.cc/v1beta/models/gemini-3.1-flash-image:generateContent \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          { "text": "生成一张 1:1 的白色陶瓷杯产品图，只返回图片。" }
        ]
      }
    ],
    "generationConfig": {
      "imageConfig": {
        "aspectRatio": "1:1",
        "imageSize": "1K"
      }
    }
  }'
原生 Gemini 多模态输入使用 parts[].inlineData 或 parts[].fileData 传参考图；这属于 Gemini 原生请求体，不要和 OpenAI Images 的 image/images/mask 字段混用。

Seedance 视频生成接口
视频生成是异步任务。使用“视频”资源组的 API 密钥调用 POST /v1/videos 创建任务，取得 id 后轮询 GET /v1/videos/{id}；任务完成后通过 GET /v1/videos/{id}/content 下载 MP4。

本地图片不需要公网 URL
客户端支持 /v1/videos 和 multipart 文件上传时，直接用 input_reference 上传本地图片。只有客户端只能发送 JSON 时，才需要使用 images 数组传入 HTTPS 图片 URL。

客户端能力	能否使用参考图	请求方式
支持 /v1/videos 和 multipart 文件上传	可以	本地文件使用 input_reference。
支持 /v1/videos 和自定义 JSON	可以	使用 images 数组传入 HTTPS 图片 URL。
只支持 /v1/chat/completions	不可以	更换支持视频接口的客户端，或直接使用下方 cURL / Python 示例。

本地参考图：直接上传文件
请求必须使用 multipart/form-data，本地图片文件字段固定为 input_reference。不要把本地路径写进 JSON，也不要把文件路径作为普通表单字符串发送。

curl -X POST "https://api.rtoc.cc/v1/videos" \
  -H "Authorization: Bearer sk-your-key" \
  -F "model=seedance-2.0" \
  -F "prompt=保持参考图主体外观一致，生成一段镜头平稳的产品展示视频" \
  -F "seconds=5" \
  -F "size=1280x720" \
  -F "input_reference=@/path/to/reference.png"
让 curl 或客户端自动生成 multipart boundary，不要手写 Content-Type。当前 Seedance 通道建议只上传 1 张本地参考图，文件小于约 4.7 MB，使用 PNG、JPEG 或 WebP。

Python requests 示例
import requests

api_key = "sk-your-key"

with open("reference.png", "rb") as image_file:
    response = requests.post(
        "https://api.rtoc.cc/v1/videos",
        headers={"Authorization": f"Bearer {api_key}"},
        data={
            "model": "seedance-2.0",
            "prompt": "保持参考图主体外观一致，生成一段镜头平稳的产品展示视频",
            "seconds": "5",
            "size": "1280x720",
        },
        files={
            "input_reference": ("reference.png", image_file, "image/png")
        },
        timeout=60,
    )

response.raise_for_status()
task = response.json()
print(task["id"])
已有 HTTPS 图片：使用 JSON
如果客户端只能发送 JSON，参考素材必须是服务器无需登录、无需 Cookie 即可稳定下载的 HTTPS URL。images 最多 4 张，videos 最多 3 段，audios 最多 1 段；字段都是字符串数组。不要在 JSON 中填写本地文件路径。

curl https://api.rtoc.cc/v1/videos \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "seedance-2.0",
    "prompt": "保持参考图中的产品外观，采用参考视频的运镜节奏，并使用参考音频作为背景声音",
    "size": "720x1280",
    "seconds": "10",
    "metadata": {
      "aspect_ratio": "9:16"
    },
    "images": [
      "https://example.com/product.png"
    ],
    "videos": [
      "https://example.com/camera-motion.mp4"
    ],
    "audios": [
      "https://example.com/background.mp3"
    ]
  }'
请求参数
参数	用法
model	必填：seedance-2.0-fast 或 seedance-2.0。
prompt	必填，最多 5000 个字符。写清主体、动作、场景、镜头运动、光线和风格。
seconds	视频时长，使用字符串 "5"、"10" 或 "15"。
size	16:9 使用 1280x720；9:16 使用 720x1280；1:1 使用 1024x1024。
metadata.aspect_ratio	与 size 保持一致，填写 16:9、9:16 或 1:1。
input_reference	multipart 专用的本地参考图片文件字段。当前 Seedance 通道建议只上传 1 张，文件小于约 4.7 MB。
images	JSON 专用的参考图片 HTTPS URL 数组，不用于上传本地文件。
videos	可选，最多 3 个视频 URL。Playground 接受 MP4、MOV、WebM，单个文件不超过 100 MB，时长 3 到 10 秒。
audios	可选，最多 1 个音频 URL。Playground 接受 MP3、M4A、WAV、AAC、OGG，单个文件不超过 15 MB，时长 2 到 15 秒。
quality	不要传。当前 Seedance 请求不使用该字段，画面比例由 size 和 metadata.aspect_ratio 控制。
查询状态与下载
API_KEY="sk-your-key"
TASK_ID="task_xxx"

curl "https://api.rtoc.cc/v1/videos/$TASK_ID" \
  -H "Authorization: Bearer $API_KEY"

curl -L "https://api.rtoc.cc/v1/videos/$TASK_ID/content" \
  -H "Authorization: Bearer $API_KEY" \
  -o result.mp4
轮询响应中的 status 会从 queued/pending 进入 processing/in_progress，最终变为 completed/done 或 failed/cancelled。建议从 3 秒间隔开始轮询，逐步增加到 10 秒；只有完成后再请求 /content。

参考图常见错误
现象	原因	处理方式
本地图片没有生效	把路径写进 JSON，或文件字段不是 input_reference。	使用 multipart，并以 -F "input_reference=@/path/to/file.png" 上传真实文件。
URL 图片没有生效	images 不是数组，或 URL 需要登录、返回 403/429、下载中断。	改用无需认证且可稳定下载的 HTTPS URL。
multipart 请求报错	手写了错误的 Content-Type 或 boundary。	删除手写的 Content-Type，让 HTTP 客户端自动生成。
提示文件过大	本地参考图超过当前 Seedance 通道限制。	将图片压缩到约 4.7 MB 以下。
No available channel for model	API Key 不属于“视频”资源组，或该 Key 看不到 Seedance。	用同一个 Key 请求 /v1/models，确认返回 seedance-2.0 或 seedance-2.0-fast。
Grok 视频生成接口
Grok 视频使用本站的异步任务接口。文生视频、单图和多参考图生成使用 POST /v1/videos；参考视频编辑使用 POST /v1/videos/edits；参考视频续写使用 POST /v1/videos/extensions。三个入口都会先返回任务 ID，再通过统一的任务查询和内容下载接口取得结果。

先确认模型名称和资源组
用同一个 API Key 请求 GET /v1/models，以实际返回的模型名为准。当前适配器识别 grok-imagine-video、grok-imagine-video-1.5 和 grok-imagine-video-1.5-preview；preview 名称是否在当前渠道开放，以模型列表为准，不要自行拼接模型名。

文生视频
curl https://api.rtoc.cc/v1/videos \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-video",
    "prompt": "电影感广角镜头，纸飞机飞过湖面，夕阳和轻微的镜头前移",
    "duration": 8,
    "aspect_ratio": "16:9",
    "resolution": "480p"
  }'
duration 使用整数秒。本站也接受游乐场兼容字段 seconds；两者同时出现时优先使用 duration。

单图生视频
curl https://api.rtoc.cc/v1/videos \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-video",
    "prompt": "保持主体外观，镜头缓慢向前推进",
    "image": {
      "url": "https://example.com/reference.webp"
    },
    "duration": 5,
    "resolution": "480p"
  }'
image 可以是包含 url、image_url 或 file_id 的对象，也可以使用兼容的字符串 URL。单图模式省略 aspect_ratio 时，适配器会让上游按输入图片比例处理；需要固定画幅时再明确传入 aspect_ratio。

多参考图生视频
多参考图必须使用原生字段 reference_images，当前网关只允许精确模型名 grok-imagine-video-1.5。提示词中使用 <IMAGE_0>、<IMAGE_1> 等占位符，编号对应数组下标。

curl https://api.rtoc.cc/v1/videos \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-video-1.5",
    "prompt": "使用 <IMAGE_0> 作为人物，使用 <IMAGE_1> 作为背景，让人物向镜头走来",
    "reference_images": [
      {"url": "https://example.com/person.jpg"},
      {"url": "https://example.com/background.png"}
    ],
    "duration": 10,
    "aspect_ratio": "16:9",
    "resolution": "720p"
  }'
最多 7 张参考图；必须有非空 prompt；参考图模式最高 720p。image 与 reference_images 不能同时出现。基础模型或 preview 即使上游偶尔接受多图，也会被本站网关拒绝，不能按这种方式使用。

预置声音（不是上传音频）
reference_audios 这个字段名容易误解：它目前不能上传或引用用户自己的 MP3、WAV 等音频文件。每一项只是从 xAI 内置语音库选择一种预置声音，写成 {"voice_id":"eve"}。当前可选声音为 ara、eve、leo、rex、sal；最多 3 项，只允许 grok-imagine-video-1.5。提示词使用 <AUDIO_0>、<AUDIO_1> 等占位符引用对应声音。

curl https://api.rtoc.cc/v1/videos \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-video-1.5",
    "prompt": "让 <IMAGE_0> 说话，使用 <AUDIO_0> 的声音",
    "reference_images": [
      {"url": "https://example.com/person.jpg"}
    ],
    "reference_audios": [
      {"voice_id": "eve"}
    ],
    "duration": 15,
    "resolution": "720p"
  }'
示例中的 eve 是 xAI 内置声音名称，不是上传音频后返回的文件 ID。当前 xAI 视频协议没有为 reference_audios 定义 URL、file_id、base64 或本地文件输入，本站也没有“上传音频后换取 voice_id”的接口。因此这里不能让模型模仿任意上传录音；它只能选用上述内置声音。使用预置声音时最高为 720p，不能请求 1080p。

Grok 参数表
参数	类型	必填	限制与说明
model	string	是	使用 /v1/models 返回的 Grok 视频模型名。
prompt	string	文生视频必填	描述主体、动作、镜头和风格。参考图/音频模式也必须提供非空提示词。
duration	integer	否	1-15 秒，省略时默认为 8；直接调用时不要传小数。
seconds	integer/string	否	本站兼容别名，转换为 duration；与 duration 不要同时传。
aspect_ratio	string	否	1:1、16:9、9:16、4:3、3:4、3:2 或 2:3。
resolution	string	否	480p、720p 或 1080p；默认 480p。1080p 仅允许 grok-imagine-video-1.5。
image	object/string	单图模式可选	单张图片 URL、data URL 或 file_id。与 reference_images 互斥。
reference_images	object[]	多图模式可选	最多 7 张；每项使用 url、image_url 或 file_id；只允许 grok-imagine-video-1.5，最高 720p。
reference_audios	object[]	可选	选择 xAI 内置声音，不是上传音频。最多 3 个 {"voice_id":"..."}；可用 ID 为 ara、eve、leo、rex、sal；只允许 grok-imagine-video-1.5，最高 720p。
video	object/string	编辑/续写必填	使用 {"url":"https://.../input.mp4"} 或 {"file_id":"..."}。本站也兼容直接传 URL 字符串，但建议使用对象形式；url 与 file_id 不能同时出现。
user	string	否	传给上游的终端用户标识，必须是字符串。
size	string	兼容字段	游乐场兼容字段，例如 1280x720、720x1280、1024x1024；直接调用建议使用 aspect_ratio。
metadata.aspect_ratio	string	兼容字段	游乐场发送的比例字段；直接调用原生参数时优先使用 aspect_ratio。
images	string[]	兼容字段	本站兼容层把 1 张转换为 image，2-7 张转换为 reference_images；仅适合传 HTTPS URL。
output / storage_options	object	否	上游存储扩展字段。只有已经取得上游要求的签名上传参数时才使用，不要自行猜字段结构。
videos / audios	array	否	其他视频适配器的通用字段；当前 Grok 适配器不会把它们转换为参考视频或参考音频。
输入格式与请求限制
Grok 视频请求必须使用 application/json；当前本站适配器不接受 multipart 本地视频上传。
参考视频编辑和续写的 video.url 必须是上游无需登录、Cookie 或请求头即可下载的公网 HTTPS 地址；也可以使用上游已经存在的 file_id。本地路径、需要鉴权的本站任务下载地址和 base64 视频不能直接使用。
图片输入优先使用 JPG、PNG 或 WebP。单图可使用公开 HTTPS URL、data URL 或上游 file_id；GIF 不属于可移植输入格式。
所有 URL 都必须能在无登录、无 Cookie、无浏览器挑战的条件下被上游下载；不要填写本地文件路径。
参考图或预置声音模式不能使用 1080p；需要 1080p 时只能使用 grok-imagine-video-1.5 的纯文生视频或单图模式。
参考视频编辑（edits）
编辑已有视频时调用 POST /v1/videos/edits。当前已验证可用的模型是精确名称 grok-imagine-video；grok-imagine-video-1.5 在该原生入口会被当前上游拒绝。

curl https://api.rtoc.cc/v1/videos/edits \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-video",
    "prompt": "把整体光线改成暖色夕阳，保留原视频的主体和运动",
    "video": {
      "url": "https://example.com/input.mp4"
    }
  }'
video 是必填项。推荐传 {"url":"..."}；如果视频已经存在于上游文件系统，也可以传 {"file_id":"..."}。编辑任务的输出时长由上游结合输入视频决定，不要用生成接口的画幅和分辨率参数推断编辑结果。

参考视频续写（extensions）
从已有视频末尾继续生成时调用 POST /v1/videos/extensions。当前已验证可用的模型同样是 grok-imagine-video。

curl https://api.rtoc.cc/v1/videos/extensions \
  -H "Authorization: Bearer sk-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-video",
    "prompt": "保持人物、镜头方向和运动连续，自然续写后续画面",
    "video": {
      "url": "https://example.com/input.mp4"
    },
    "duration": 6
  }'
duration 表示续写时长，只能是 2-10 秒的整数；省略时上游默认续写 6 秒。编辑和续写请求都会返回 {"request_id":"task_xxx"}，后续查询与下载方式和普通视频生成完全相同。

能力	游乐场当前状态	限制

单图生视频	支持	上传或粘贴 1 张图片，转换为 image。

查询状态与下载
API_KEY="sk-your-key"
TASK_ID="task_xxx"

curl "https://api.rtoc.cc/v1/videos/$TASK_ID" \
  -H "Authorization: Bearer $API_KEY"

curl -L "https://api.rtoc.cc/v1/videos/$TASK_ID/content" \
  -H "Authorization: Bearer $API_KEY" \
  -o result.mp4
状态通常经历 queued、in_progress、completed 或 failed。建议从 3 秒间隔开始轮询，逐步增加到 10 秒；只有完成后再请求 /content。如果任务创建成功但上游返回 URL 失效，优先使用本站的 /content 代理。

常见错误
现象	原因与处理
reference-to-video requires grok-imagine-video-1.5	多参考图或参考音频必须改用精确模型名 grok-imagine-video-1.5。
prompt is required for reference-to-video	参考图或预置声音模式必须有提示词，并用 <IMAGE_n> 或 <AUDIO_n> 指向对应数组项。
image and reference_images cannot be combined	单图和多参考图只能二选一。
reference_images supports at most 7 images	删除多余参考图，网关上限为 7 张。
参考模式请求 1080p 被拒	参考图/音频模式最高 720p；1080p 仅用于 1.5 的纯文生或单图模式。
图片格式错误	改用 JPG、PNG 或 WebP；不要使用 GIF，也不要把本地路径写入 JSON。
编辑或续写请求返回 400	先确认模型使用精确名称 grok-imagine-video，并确认 video 包含可公开下载的 url 或有效 file_id。续写的 duration 必须为 2-10 秒整数。
